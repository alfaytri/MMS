RPC(s)

Ledger writes / side-effects on write
For p_qty_good &gt; 0: (a) fifo_cost_layers fresh layer at source warehouse with source_type=&#39;damaged_repair_return&#39;, source_id=&lt;outbound transfer id&gt;, unit_cost = original_unit_cost + (p_repair_cost / p_qty_good) — repair cost amortized across good units only; (b) inventory_item_brand_variants.stock_level += qty_good; (c) inventory_stock_movements(movement_type=&#39;damaged_return_from_repair_as_good&#39;) — NEW enum value added by this migration; (d) recalc_average_cost(variant_id) weighted-avg recompute; (e) warehouse_transfers row (from=vendor virtual warehouse, to=source, transfer_kind=&#39;damaged_repair_return_good&#39;, status=&#39;received&#39;, repair_cost=&lt;p_repair_cost&gt;, source_return_line_disposition_id = same disposition as the outbound); (f) warehouse_transfer_items normalized child row. For p_qty_writeoff &gt; 0: (a) inventory_damaged_movements(movement_type=&#39;return_from_repair_as_writeoff&#39;) linked to both disposition and outbound transfer — writeoff units use the ORIGINAL unit cost (no repair-cost inheritance; that spend is sunk); (b) warehouse_transfers row with transfer_kind=&#39;damaged_repair_return_writeoff&#39;, status=&#39;received&#39; — no stock added, but the row exists so the Damaged Stock overview page's join logic doesn't have to special-case the "outcome had no good units" shape; (c) warehouse_transfer_items normalized child row with received_qty=0. Finally: outbound transfer UPDATE to status=&#39;received&#39;, received_at=now(), received_by_profile_id=auth.uid(), repair_cost=&lt;p_repair_cost&gt;.
Downstream side-effects
Damaged stock at source warehouse is not affected by this RPC directly (the send_for_repair_out movement already decremented it in 9.4; good units return to inventory_stock not damaged stock). Good units are immediately available for normal sale. The vendor's virtual warehouse still doesn't hold any aggregate stock — the transfer rows are the record of location.
Dialog / component
ReturnFromRepairDialog (Phase 9.7). Client-side validation must enforce qty_good + qty_writeoff == transfer_qty.
Guards / preconditions
Outbound transfer must have transfer_kind=&#39;damaged_repair_out&#39; and status=&#39;in_transit&#39;. qty_good + qty_writeoff must equal the outbound transfer's qty (server-side). p_repair_cost &gt;= 0. Outcome sanity: good requires qty_writeoff=0, writeoff requires qty_good=0, mixed requires both > 0.
Related flows
Send Damaged for Repair (produces the outbound transfer this RPC consumes), Record Inventory Disposition (post-restock) (originates the disposition both transfers share).
